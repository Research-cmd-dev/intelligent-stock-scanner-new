1. PROJECT OVERVIEW & MISSION
================================================================================

Primary Mission:
To proactively identify emerging and under-appreciated narratives across high-growth 
sectors (AI infrastructure, biotechnology, robotics, space, power, etc.) and surface 
technically clean chart setups that offer strong asymmetric upside potential for 
longer-term investment.

Core Philosophy:
- Technicals are the foundation — the chart must show something meaningful.
- Narrative and catalysts are major multipliers.
- Quality dramatically outweighs quantity.
- Focus on macro/swing timeframes, not day trading.
- Serve as a high-quality idea generation engine with a smart, persistent watchlist.

Supporting Capability:
Deep fundamental research (via LLMResearcher) acts as a secondary validation layer 
that activates only on the highest-conviction setups (composite score >= 70).

We are now using **Grok Build** as the primary coding agent (documented in PROJECT.md).

2. DETAILED ARCHITECTURE & LAYER BREAKDOWN
================================================================================

--- 2.1 Core Data Layer (src/data/) ---
- polygon_client.py: Direct REST calls to Polygon aggregates endpoint. 
  Handles lookback calculations using get_current_utc_date().
- yfinance_client.py: Fallback data source. Normalizes index to tz-naive date.
- fetcher.py: Unified entry point. Tries Polygon first, falls back to yfinance.
  Implements disk cache (data/cache/) with freshness check using 
  get_current_utc_date(). Critical for dashboard performance.
- historical.py: Durable long-term OHLCV store (data/historical/{SYMBOL}.parquet).
  - Incremental updates with gap detection + 7-day pad.
  - Atomic writes using .tmp + os.replace pattern.
  - ThreadPoolExecutor for parallel downloads.
  - Supports warm_cache_from_historical() to feed the existing fetcher cache.
- __init__.py: Exposes fetch_ohlcv, load_history, load_panel, etc.

--- 2.2 Configuration & Sectors (src/config/) ---
- sectors.py: Curated thematic universe (AI Chips, Biotech, Robotics, Space, 
  Nuclear, etc.) plus ETF proxies and broad market symbols.
- settings.py: Environment loading via dotenv. Supports POLYGON_API_KEY, 
  ANTHROPIC_API_KEY, X_BEARER_TOKEN, TWITTER_BEARER_TOKEN, STOCK_DATA_ROOT.

--- 2.3 Utilities (src/utils/) ---
- logging.py: Centralized logger.
- time.py (NEW): 
  - get_current_utc_datetime() → timezone-aware UTC datetime
  - get_current_utc_date() → UTC date object
  - Used everywhere for "today" decisions to eliminate timezone drift.

--- 2.4 Scanner Layer (src/scanner/) ---
- indicators.py: add_indicators() — adds SMA20/50/200, EMA21, RSI14, ATR14, 
  vol_sma20, returns, drawdown_120, SMA slopes, distance-from-MA, etc.
  Column names are exported as constants (no string literals in detectors).
- patterns/
  - base.py: MatchResult dataclass, Factor, clamp(), triangular() scoring helpers.
  - trend_rider.py: Trend-following pattern with hard gates (SMA50 > SMA200, 
    price > SMA200, dist_sma50 in [-5%, +10%], etc.).
  - bottom_hunter.py: Reversal pattern after significant damage + basing.
- universe.py: Builds discovery list from sectors + thematic ETFs.
- scanner.py: Orchestrates fetch → indicators → detectors → optional narrative → 
  optional research.

--- 2.5 Narrative Layer (src/narrative/) — Major Recent Enhancement ---
- sources/
  - base.py: NewsSource protocol + NewsItem dataclass + dedup_key logic.
  - polygon_news.py, yfinance_news.py: Existing news adapters.
  - x_accounts.py (NEW): HIGH_QUALITY_X_ACCOUNTS list (16 accounts as of latest update, 
    including unusual_whales).
  - x_news.py (NEW): XAccountsNewsSource — queries X API v2 recent search using 
    from:account (SYMBOL OR $SYMBOL) patterns. Returns NewsItem with provider="x".
    Falls back silently if no X_BEARER_TOKEN.
- sentiment.py: LexiconSentiment (prefers external_sentiment when present).
- themes.py: Keyword-based detection of narrative themes with core_terms, 
  support_terms, and required_pairs for composites.
- catalysts.py: Phrase-based detection of discrete events (contract, partnership, 
  pivot, etc.) with strong_phrases for higher strength.
- scorer.py: NarrativeScorer — fetches from all sources, scores sentiment, 
  detects themes/catalysts, applies recency decay (half-life 5 days), applies 
  conviction boosts, produces NarrativeResult.
  - X posts receive an additional _X_MOMENTUM_BOOST (0.12) when they have 
    theme or catalyst signal.
- cache.py: Daily news cache (data/cache/news/{SYMBOL}_YYYY-MM-DD.json) using 
  get_current_utc_date() for keys.

--- 2.6 Dashboard (src/dashboard/app.py) ---
- Thin Streamlit view.
- Supports Discovery scan and Watchlist mode.
- Narrative weight slider, research expanders, per-match detail.
- Uses @st.cache_data with frozen ScanParams.

--- 2.7 Backtest & Self-Refinement (src/backtest/) ---
- signals.py: Bar-by-bar replay using Scanner.scan_frame() on historical slices.
- engine.py: Trade simulation with next-bar entry, hold period, cooldown.
- metrics.py + refine.py: Full metrics + deterministic improvement suggestions.
- Supports feature evaluation via --evaluate-features.

--- 2.8 Features Layer (src/features/) ---
- alpha158.py, custom.py, evaluator.py, pipeline.py.
- Computes IC/IR for feature quality assessment during backtests.

--- 2.9 Research Layer (src/research/) ---
- base.py: ResearchResult dataclass, Researcher protocol, conviction gate helpers.
- llm_researcher.py: Production implementation using Anthropic with:
  - Prompt caching on system prompt.
  - Structured JSON output matching ResearchResult schema.
  - One call per unique high-conviction symbol (research_limit).
- Fully wired into Scanner and dashboard.

--- 2.10 Modal Compute Layer (src/modal_app/ + src/data/historical.py) ---
- Durable historical store designed to work identically locally and on Modal.
- Remote functions for heavy downloads and backtests.
- AVAILABLE_TOOLS catalog for future agent use.

--- 2.11 Date/Time Standardization (Critical Recent Work) ---
- Problem: Mix of date.today() (local) and datetime.now(tz=timezone.utc) caused 
  off-by-one day errors in cache checks and incremental logic, especially in 
  cloud environments.
- Solution: All "current day" logic now uses get_current_utc_date() from 
  src/utils/time.py.
- Files updated: historical.py, polygon_client.py, fetcher.py, 
  narrative/sources/cache.py.
- Test impact: Fixed the flaky `test_request_shape_matches_prompt_caching_contract` 
  that relied on hardcoded dates.

5. HOW TO RUN (DETAILED)
================================================================================

Dashboard:
  streamlit run src/dashboard/app.py

Historical Data (Local):
  python -m src.data.historical download --all --workers 12
  python -m src.data.historical download --symbols NVDA,PLTR
  python -m src.data.historical info NVDA

Backtesting:
  python -m src.backtest.run --symbols NVDA,PLTR --start 2024-01-01
  python -m src.backtest.run --evaluate-features --start 2024-01-01

Modal (requires modal + token):
  modal run src.modal_app.app::download --symbols NVDA,PLTR
  modal run src.modal_app.app::backtest --symbols NVDA,PLTR \
      --start 2024-01-01 --end 2026-05-01

Enabling X Signal:
  export X_BEARER_TOKEN=your_token   # or TWITTER_BEARER_TOKEN
  # Then run any scan or backtest that uses narrative scoring

Enabling Deep Research:
  export ANTHROPIC_API_KEY=...
  # Research automatically activates on matches >= 70 composite score

Tests:
  pytest -q
  pytest tests/test_research_llm.py -q --tb=short   # specific date-sensitive tests

- **Modal Download Entry Point Enhancement (Proposed - Option 2)**:
  Currently the Modal wrapper (`src/modal_app/app.py` → `download` local_entrypoint) 
  only supports `--symbols`, `--force`, and `--workers`. It does **not** accept 
  `--sector` or `--days`, unlike the local historical CLI.

  **Proposed change**: Extend the `download` function to also accept:
    - `--sector "AI" "Chips" "Nuclear" ...` (one or more sectors)
    - `--days 5500` (or `--lookback-days`)

  When sectors are provided, the entrypoint would internally resolve them into 
  the full ticker list using `src/config/sectors.tickers_for_sectors()`, then pass 
  the expanded list to `download_universe_remote`.

  **Why this is valuable**:
    - Dramatically better UX consistency between local (`python -m src.data.historical download`) 
      and remote (`modal run ...`) usage.
    - Users can trigger large sector-based refreshes without manually listing 40+ symbols.
    - Makes it easy to do commands like:
        modal run -m src.modal_app.app::download \
          --sector "AI" "Chips" "Nuclear" "Space" "Power" "Robotics" \
          --days 5500 \
          --workers 12 \
          --force
    - Still keeps the simple `--symbols` path for quick targeted refreshes.

  **Implementation approach**:
    - Modify the `download` local_entrypoint signature to accept optional `sector: str` 
      (comma or space separated) and `days: int`.
    - If sectors are provided, resolve them to symbols (import the existing resolver 
      to avoid duplication).
    - If both `--symbols` and `--sector` are passed, either error or merge them.
    - Pass the final symbol list + force + workers to the remote function (no change needed there).
    - Update the docstring and any Makefile targets accordingly.

  **Trade-offs**:
    - Slightly increases complexity of the Modal entrypoint (from very thin to light logic layer).
    - Minor risk of drift if sector logic changes (mitigated by importing the canonical function).
    - Still very small change overall (~15-25 lines).

  This is a high-value, low-risk improvement for daily workflow when working with 
  Modal from Codespaces.
