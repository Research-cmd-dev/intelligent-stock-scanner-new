   - src/config/ — sectors universe + settings (env loading)
   - src/data/ — Polygon + yfinance clients, unified fetcher with on-disk
     parquet cache, PLUS durable historical store (new — see Modal Compute
     Layer section below)
   - src/utils/ — logging
   - src/scanner/ — indicators, universe builder, Trend Rider + Bottom Hunter
     detectors, Scanner class, MatchResult + Factor scoring (committed)
   - src/narrative/ — full intelligent narrative layer (committed, then enhanced):
       * sources/  — NewsSource protocol, Polygon + yfinance adapters,
                     on-disk JSON cache (data/cache/news/), dedup
       * lexicon.py    — finance-flavored positive/negative word + phrase lists
       * sentiment.py  — Sentiment protocol + LexiconSentiment
                         (prefers Polygon's per-article external_sentiment
                         when present, falls back to lexicon)
       * scorer.py     — NarrativeScorer.score(ticker) -> NarrativeResult,
                         recency-weighted aggregation (5-day half-life),
                         thin-coverage damping, explanation builder,
                         blend_composite() (80% pattern / 20% narrative default)
       * themes.py     — ThemeDef catalog with composite required_pairs:
                           - Miner-to-AI Pivot (BTC miner + AI/HPC)
                           - Power + Compute (cheap power/PPA/hydro + GPU/AI)
                           - Neocloud / GPU Cloud
                           - Data Center Build-out (DC + megawatt/gigawatt/construction)
                           - Nuclear for AI (SMR/nuclear + AI/DC)
                           - AI Infrastructure
                           - Sovereign AI
                         detect_themes(text) -> list[ThemeTag] +
                         aggregate_themes() across items.
       * catalysts.py  — Kinds: contract, funding, expansion, pivot, m_and_a,
                         earnings_beat, partnership, approval.
                         Each has phrases + strong_phrases (anchor customer,
                         oversubscribed, gigawatt-scale, fully pivoting...).
                         detect_catalysts(text) -> list[CatalystTag] +
                         aggregate_catalysts().
       * scorer integration of themes + catalysts:
                         per-item conviction boost =
                           0.30 * max(theme.relevance) +
                           0.30 * max(catalyst.strength)
                         multiplies the recency weight in _aggregate_polarity.
                         Sign-preserving — themes amplify, never override.
                         NarrativeResult exposes .themes and .catalysts;
                         to_row() exposes narrative_themes + narrative_catalysts;
                         explanation surfaces them when aggregate >= 0.4.
   - Scanner integrated with narrative layer: MatchResult has
     `narrative` + `composite_score` fields; `effective_score` property
     ranks by composite when present, pattern score otherwise.
     Narrative scoring only runs on symbols that produced a pattern hit
     (one news fetch per unique symbol).
   - src/dashboard/ — Streamlit dashboard (committed):
       * app.py — thin view over Scanner + run_scan
       * Sidebar: Discovery vs Watchlist mode, sector multi-select,
                  pattern toggles (Trend Rider / Bottom Hunter), min-score,
                  lookback, ETF coverage, narrative overlay + weight slider
       * Main: summary metrics row, ranked table with progress-bar Score
               + Composite columns, "Key Signal" derived from top factor,
               CSV download, per-match detail (factors + headlines +
               research expander), diagnostics expander
       * @st.cache_data keyed off a frozen ScanParams dataclass (1h TTL)
       * Launch: `streamlit run src/dashboard/app.py` (or `make run`)
   - src/backtest/ — backtest + self-refinement loop (committed):
       * signals.py — generate_signals() replays the scanner bar-by-bar
                       across history (fetch once, enrich once, slice
                       forward). Reuses live scanner code — no
                       second implementation to drift.
       * engine.py  — run_backtest(), simulate_trades() (next-open entry,
                       N-day hold, optional cooldown), BacktestReport
                       dataclass holding signals + trades + metrics +
                       breakdowns + optional Qlib block + optional
                       features_evaluation.
       * metrics.py — win rate, mean/median return, profit factor,
                       max drawdown, sharpe_like, breakdown_by(pattern|sector),
                       breakdown_by_score_band; compute_qlib_metrics()
                       routes through qlib.contrib.evaluate.risk_analysis
                       when `qlib` is importable, returns None otherwise.
       * refine.py  — deterministic Suggestion heuristics, no LLM/ML:
                       (1) pattern win-rate gap, (2) low-vs-high score
                       band gap, (3) sector bias, (4) negative mean return,
                       (5) PF < 1, (6) feature IC promotion (|IR| >= 1.0),
                       (7) feature IC deprecation (|IR| < 0.3).
                       Coverage gates keep thin samples silent.
       * report.py  — writes logs/backtest_{YYYYMMDD_HHMMSS}.md
                       + appends a dated block to logs/suggestions.md.
       * run.py     — CLI: `python -m src.backtest.run --symbols ...`
                       or `--sector AI Chips ...` or no args for the
                       full thematic universe. Flags: --evaluate-features,
                       --feature-horizon N. Prints one-line summary +
                       top 5 features by |IR| + every suggestion title.
   - src/features/ — feature engineering layer (committed):
       * alpha158.py — ~21 Alpha158-style features in pandas
                       (KMID, KLEN, KUP, KLOW, KMID2, KSFT, ROC5/10/20/60,
                        MA5/20/60, STD5/20, BETA20, VMA5/20,
                        IMAX5, IMIN5, QTLU20).
                       Optional pass-through to real Qlib Alpha158 when
                       pyqlib + a Qlib data dir are available; clean
                       fallback otherwise.
       * custom.py  — scanner-derived (RSI14_Z60, DIST_SMA50_Z60,
                       DIST_SMA200_Z60, DRAWDOWN_120, DRAWDOWN_120_Z60,
                       PULLBACK_DEPTH, TREND_REGIME), sector-relative
                       (SECTOR_RELATIVE_5D / 20D — symbol return minus
                       sector cohort's median), and narrative-snapshot
                       (NARRATIVE_SCORE).
       * evaluator.py — cross-sectional Spearman IC per date, aggregated
                       to mean_ic / std_ic / IR / t-stat / N. Gates:
                       MIN_SYMBOLS_PER_DATE (5), MIN_OBSERVATIONS (50).
                       Output sorted by |IR| desc.
       * pipeline.py — build_feature_evaluation(symbols, start, end,
                       forward_horizon=5) end-to-end: fetch -> enrich ->
                       compute -> panel -> IC.
   - src/research/ — DEEP RESEARCH LAYER (scaffold + first real
                     implementation + scanner/dashboard wiring all landed):
       * base.py    — ResearchResult dataclass with the mission's six
                      validation slots (summary, company_quality,
                      management, partnerships, financial_health,
                      key_risks, sources, confidence in [0,1], raw).
                      Researcher protocol (@runtime_checkable).
                      NullResearcher baseline returning an empty
                      ResearchResult so the integration layer can call
                      .research(sym) unconditionally.
                      should_research(score, threshold=70.0) +
                      top_candidates(matches, threshold, limit=5,
                                     unique_by="symbol") — the conviction
                      gate keeping research as opt-in secondary validation
                      rather than a per-symbol cost on idea generation.
       * llm_researcher.py — first real Researcher: Anthropic-SDK-backed
                      synthesizer over the same headline basket the
                      narrative scorer collected. Defaults to
                      claude-sonnet-4-6 with prompt caching on the
                      rubric system prompt + structured-output JSON
                      schema mirroring ResearchResult. Per-call timeout
                      30s, max_tokens=1024. Fails soft to empty result
                      with confidence=0.0 (no key, API error, malformed
                      JSON — all treated the same).
       * Wired into Scanner + dashboard (commit 7e94117):
                      - MatchResult gained a nullable `research` field
                        alongside `narrative`; to_row() exposes
                        research_summary + research_confidence.
                      - Scanner(researcher=..., research_limit=5) runs
                        the enrichment AFTER narrative scoring + after
                        min_score filter + sort, so research operates on
                        the final ranked list and never re-orders it.
                      - Selection uses top_candidates(... unique_by=
                        "symbol") so a multi-pattern hit on one symbol
                        consumes exactly ONE research slot.
                      - Researcher failure on any one symbol is logged
                        and skipped — that symbol's matches keep
                        research=None, scan continues.
                      - Dashboard per-match detail expander renders a
                        collapsible "Deep research (fundamental read)"
                        subsection: confidence progress bar, summary,
                        then company_quality / management / partnerships
                        / financial_health / key_risks. Empty payload
                        renders as a one-line caption.

4. How to run the full system:
   - Live dashboard:
       streamlit run src/dashboard/app.py     # or: make run
   - Local historical data:
       python -m src.data.historical download --sector "AI" "Chips"
       python -m src.data.historical download --all --workers 12
       python -m src.data.historical info NVDA
       python -m src.data.historical list
   - Backtest with suggestions:
       python -m src.backtest.run --symbols NVDA,PLTR --start 2024-01-01
       python -m src.backtest.run --sector AI Chips --start 2024-01-01
       python -m src.backtest.run --start 2024-01-01     # full universe
   - Backtest with feature evaluation:
       python -m src.backtest.run --evaluate-features --start 2024-01-01
       python -m src.backtest.run --evaluate-features --feature-horizon 10 \
           --sector AI Chips --start 2024-01-01
   - Modal compute:
       modal token new                                            # one-time auth
       modal run src.modal_app.app::download --symbols NVDA,PLTR
       modal run src.modal_app.app::backtest --symbols NVDA,PLTR \
           --start 2024-01-01 --end 2026-05-01
       # Or via Makefile:
       make modal-download SYMBOLS=NVDA,PLTR,AMD
       make modal-backtest SYMBOLS=NVDA,PLTR START=2024-01-01 END=2026-05-01
   - Tests:
       pytest -q          # 130 passing

5. Optional enhancements (not required to run):
   - `pip install pyqlib` enables annualized risk_analysis (information
     ratio, annual return, max DD) on top of the in-house metrics, and
     enables the real Alpha158 handler when a Qlib bin-data dir is set
     up.
   - `pip install modal` enables the Modal compute layer. Without it
     the rest of the system runs identically.
   - `ANTHROPIC_API_KEY` in .env enables LLMResearcher. Without it the
     constructor still succeeds and every research() call returns an
     empty result with confidence=0.0 — same contract as a network
     failure.

6. What the recent layers help with:
   - Narrative enhancement (themes + catalysts): under-followed
     small-cap AI-infra setups whose thin news basket happens to be
     the *right kind* (miner-to-AI pivot + hyperscaler contract +
     capacity expansion) clear damping and produce a clear bullish
     score plus a one-line thesis instead of a neutral summary.
   - LLMResearcher: on the same setups, surfaces a structured
     fundamental read (company quality, management, partnerships,
     financial health, risks) inside the dashboard's per-match
     expander — only for matches that clear composite >= 70.0, capped
     per scan. Cents per run with Sonnet 4.6 + prompt caching.
   - Modal compute: cold-pulling 5+ years of OHLCV for 1k-5k symbols
     finishes in minutes inside a 4-CPU container with 16 workers;
     subsequent incremental updates pull just the gap. Full-universe
     backtests run against a version-locked image with the volume
     pre-warmed — no Codespace memory limits, no overnight downloads
     blocking the dashboard.
